Matrice des guides et des senseurs

Un guide oriente l’agent avant ou pendant son travail (feedforward). Un senseur observe le code ou son comportement et lui fournit un retour (feedback).

Guide · consignes en amont Senseur · retour sur le résultat
Mécanismes repérés dans le dépôt Gesta
Type Guide — feedforward Senseur — feedback
Inférentiel
(interprété par une IA)
  • Les instructions de Copilot orientent l’agent sur l’architecture, les conventions et les validations.
  • Le README apporte le contexte du projet et de ses objectifs.
  • Le cahier des charges décrit les exigences métier à interpréter avant de développer une fonctionnalité.
Aucun senseur inférentiel automatique n’est configuré dans le dépôt. Le modèle de pull request invite à la revue, mais n’effectue pas lui-même de revue par IA.
Computationnel
(règles ou calculs exécutables)
  • Le package.json fixe la version minimale de Node.js et propose les commandes de vérification.
  • Les configurations TypeScript et Oxlint définissent des règles exécutables.
  • Les tests décrivent aussi des comportements attendus : ils peuvent guider l’implémentation avant d’être lancés.
  • npm run lint, npm run typecheck, npm test et npm run build signalent les problèmes détectés.
  • Les tests API des offres vérifient notamment les droits et les filtres ; les tests de la page des offres vérifient l’affichage et les interactions.
  • Le contrôle de version de Node.js indique si la version est trop ancienne ; les tests associés vérifient les versions acceptées et refusées.

À retenir : les instructions de Copilot guident l’agent sans exécuter de vérification ; le cahier des charges donne les exigences métier à interpréter. Les tests unitaires ont un double rôle : leurs attentes guident l’implémentation, puis leur exécution vérifie le résultat et signale les écarts.
