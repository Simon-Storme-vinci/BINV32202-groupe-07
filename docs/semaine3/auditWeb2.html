Audit des guides à la lumière de Web 2

Comparaison des consignes du dépôt avec des attentes effectivement repérées dans les supports Web 2, sans transformer une pratique de projet en exigence du cours.

Périmètre et méthode

Guides lus : instructions Copilot, README, architecture, cahier des charges, contrat API et modèle de pull request. Aucun fichier AGENTS.md n’a été trouvé. Les références Web 2 ci-dessous pointent vers les pages précises des PDF du dossier web2/. « Partielle » signale une ressemblance réelle, mais pas une règle identique ou applicable à toute l’architecture.

Comparaison des attentes et des guides

Correspondances vérifiables entre les supports Web 2 et les consignes du dépôt.
Attente ou convention Web 2 (source) Guide examiné (fichier et passage) Correspondance Écart ou ajout proposé
Conventions HTTP / REST Séance 02, p. 3–4 : verbes HTTP associés aux opérations et paramètres de requête utilisés pour préciser une recherche. backend/API.md décrit les routes, méthodes et paramètres, par exemple GET /offers?period=…. Les instructions Copilot demandent de mettre à jour le contrat API et la requête HTTP correspondante. Oui Rien d’important à ajouter : conserver la synchronisation entre route, documentation et exemple REST Client.
Modèles et organisation des fichiers frontend Séance 10, p. 2–4 présente l’organisation des fichiers, un modèle typé dans models/recipe.ts et un module de données séparé. docs/architecture.md sépare modèles, services, hooks, composants et pages ; le README explique le choix TypeScript. Partielle La séparation frontend est cohérente. Les couches backend contrôleurs/services/repositories sont une convention propre à Gesta ; ne pas les présenter comme une exigence de Web 2 sans support correspondant.
Props : données transmises du parent à l’enfant Séance 08, p. 3 définit les props comme les données passées par le composant parent au composant enfant. Les instructions Copilot disent que App possède l’état d’authentification et transmet le jeton et le callback de déconnexion aux pages. L’architecture précise que les composants réutilisables ne connaissent pas les routes. Oui Le principe est explicite et cohérent ; garder cette règle lors de l’ajout d’autres états partagés.
État partagé remonté au plus proche parent commun Séance 14, p. 3–4 : remonter l’état au parent commun, puis passer aux enfants la valeur et une fonction de mise à jour. Les guides attribuent explicitement la session à l’unique useAuth dans App et interdisent aux pages de recréer leur propre état d’authentification. Oui Bonne traduction du principe du cours ; le guide pourrait préciser que cette propriété unique concerne l’état partagé, sans imposer de remonter tout état local des composants.
Handlers React : passer une fonction, ne pas l’exécuter au rendu Séance 12, p. 3–4 illustre la différence entre passer un handler et appeler immédiatement la fonction dans le JSX. Les guides décrivent les responsabilités des pages et composants, mais ne formulent pas cette convention d’événement. Absente Ajouter une courte règle aux conventions frontend, avec un exemple onClick={handleAction} et une mention des fonctions fléchées lorsque des arguments doivent être transmis.
Authentification et protection des mots de passe Séance 03, p. 3 présente le JWT comme preuve d’identité transmise aux requêtes. Séance 04, p. 2–3 indique de ne pas stocker les mots de passe en clair et de conserver un hash. Architecture et API indiquent que le jeton ne porte que l’identité et que rôles/droits sont relus en base. Le README précise que la connexion actuelle est passwordless, réservée au développement et refusée en production. Partielle Pas de contradiction pour le mode démo : aucun mot de passe n’y est stocké. Le choix de ne pas placer les rôles dans le JWT est différent de l’exemple de cours, mais le guide explique la relecture en base. Pour une future authentification réelle, rappeler explicitement le hachage des mots de passe.

Sujets non conclus faute de source probante

Les guides du dépôt imposent la validation HTTP côté contrôleurs (instructions Copilot) et documentent les erreurs de requête dans l’API. Cependant, les passages Web 2 cités ici sur les événements input/submit ne prescrivent pas de règles de validation des valeurs. Je ne qualifie donc pas cette validation d’attente Web 2. De même, aucun passage précis sur l’accessibilité n’est retenu : ce rapport ne conclut ni à une conformité ni à une lacune du cours sur ce sujet.

Conclusion. Les consignes Gesta sont bien alignées avec les supports Web 2 sur REST, props et état partagé React. L’organisation frontend est cohérente, tandis que les couches backend relèvent du projet. Le manque le plus directement justifié par les supports examinés est l’absence d’une règle explicite sur le passage des handlers React. Le traitement du JWT et le mode de démonstration sont documentés et ne contredisent pas les supports ; il serait utile de conserver cette distinction lors d’une future authentification réelle.

Aucun guide du dépôt n’a été modifié. Les recommandations de ce document sont des propositions d’audit, pas des changements appliqués.
